# Security policy

Security fixes are provided for the latest released minor version.

Use GitHub private vulnerability reporting. Do not open public issues for
authorization bypasses, SQL injection, option allowlist bypasses, XSS,
prototype pollution, credential exposure, stale AJAX data, unsafe downloads,
or installation downgrade/incompatibility. Include a synthetic reproduction,
affected version, impact, and mitigation when possible.

Never submit production data, tokens, cookies, private URLs, wallets, customer
assets, collaborator details, or authenticated screenshots. Maintainers aim to
acknowledge complete reports within seven days and coordinate disclosure after
a fix is available.

Consumers remain responsible for authentication, server-side authorization,
binds, organizational scope, credentials, code review, database locks, and
deployment controls.
